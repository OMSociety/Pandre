# 双盘聚合客户端 · 开发文档

> **这份文档是什么**：两盘接口的逆向取证与实现规格。协议细节、参数口径、errno 映射、架构决策、工程约定与 UI 陷阱都在这里；改协议或改界面之前先读对应章节。
>
> **一句话定义**：用 Avalonia UI（.NET 10 LTS）写的跨平台桌面客户端（Windows 先行，macOS/Linux 跟随），项目名 Pandre，中文名「盘多录」，聚合**百度网盘**和**夸克网盘**，纯 C# 直连两家的 Cookie 接口，零广告零捆绑，绿色免安装。

---

## 1. 功能范围

| 类别 | 功能 |
|---|---|
| 浏览 | 双盘文件列表与目录导航 |
| 搜索 | 当前网盘全盘搜索（按官方搜索接口翻页取全） |
| 文件管理 | 新建文件夹、重命名、删除（移动、复制在抽象层有方法，界面暂无入口） |
| 下载 | 取真实下载链 → aria2 多线程下载、断点续传、队列与暂停继续 |
| 上传 | 小文件直传、大文件分片、夸克断点续传 |
| 分享 | 创建（有效期与提取码可选）、列出、取消 |
| 转存 | 粘贴别人的分享链接（含提取码）→ 存进自己盘 |
| 离线下载 | 磁力/电驴链接 → 云端下载完成后拉回（仅百度） |
| 账号 | 容量配额显示 |
| 图片预览 | 列表内缩略图 |

**范围外**：

- 破解限速、官方会员功能；视频在线播放、文档在线预览、跨盘搬运、在线解压；相册备份、同步空间。
- 多账号切换（当前只保留单个登录态）。
- Android / iOS 移动端（维护成本不成比例）。
- **秒传链接（bdpan:// 导入）**。用油猴文档的公开样例（`md5=d5aabefc3290f7a3c09912228b136d0c`、`slice-md5=821a9f0d27fcd19c80474d2140ed2d85`、`size=6467659`）连同盘上自有的同哈希文件作判决性测试，当期三条通道全部不可用，证据见 §4c。上传链路的秒传命中（同名同哈希文件已在盘上时瞬完）是另一条路径，不受影响。

## 2. 架构决策

**选型：纯 C# 直连两家 Cookie 接口。** 不采用本地后端聚合（OpenList / AList 一类）方案：那要把一个本地服务器连同它的依赖一起分发，体验上限被其 API 封死，百度驱动还依赖随时可能失效的祖传共享密钥。

**登录只做扫码，无手动粘贴入口。** 设置页为「扫码登录」按钮 + 登录状态显示；Cookie 过期（夸克以周计）后统一检测失效响应，明确提示「请重新扫码」，不静默失败。百度扫码用「百度网盘 App」或「百度 App」扫，夸克扫码用「夸克网盘 App」或「夸克 App」扫。

**为什么走网页 Cookie 接口而不是复刻桌面端协议**（逆向取证证据）：

- 两家 PC 客户端都是 Electron 套壳。百度网盘 8.8.8：`module\BrowserEngine\resources\app.asar`（226 MB，package.json 显示 `@baidu/disk-core` 等内部包）；夸克网盘 3.24.0：`app-3.24.0\resources\app.asar`（126.6 MB）。
- 夸克客户端带 `SecurityGuardSDK64.dll`（阿里聚安全）+ `UTDID.dll`，**桌面端私有请求有设备指纹签名层**，复刻成本高且容易触发风控；网页接口（`drive-pc.quark.cn`）只需 Cookie，已被 quarkpan / QuarkPanTool / OpenList 驱动长期验证。
- 百度客户端的协议栈在 native 层 `kernel.dll`（42 MB），JS 壳里几乎没有接口路径。对 kernel.dll 做了字符串提取（非反汇编），实锤端点见 §3 端点表，与 BaiduPCS-Go 源码相互印证。
- 网页版功能足以覆盖 §1 的功能表；桌面端多出来的同步空间、相册备份本就在范围外。扫码登录与 Cookie 路线不矛盾——扫码就是拿 Cookie 的手段。

## 3. 百度网盘接口（Cookie 路线）

**为什么不用官方开放平台**：新申请应用只能访问 `/apps/<应用名>` 单一目录，全盘权限基本不批；个人开发者拿不到分享 API。

**认证**：浏览器登录 pan.baidu.com 后取 Cookie `BDUSS` + `STOKEN`；`devuid`（设备标识，BaiduPCS-Go 有生成算法）为 BaiduPCS-Go 部分接口所需，本项目实测未使用。

**扫码登录链路**：

1. `GET passport.baidu.com/v2/api/getqrcode?lp=pc` → `sign` + `imgurl`（imgurl 无 scheme，需补 `https://`）。
2. 长轮询 `GET passport.baidu.com/channel/unicast?channel_id={sign}&…`：`channel_v` 里 `status=1` 已扫码、`status=0` 已确认并给出 `v`。
3. `GET passport.baidu.com/v3/login/main/qrbdusslogin?bduss={上一步 unicast 返回的 v}&u=…&qrcode=1&tpl=netdisk&apiver=v3&tt=…` → 返回 200 伪 JSON（单引号 + `&quot;` 转义）。**参数名是 `bduss`，值取 unicast 的 `v`**（不是 `?…&v=…`）。**坑：Set-Cookie 里的 BDUSS 对 pan.baidu.com 无效**（quota 400、disk/main 302 回登录页）；真凭证在响应体 `session` 字段里，须正则抽取 `"bduss":"([^"]+)"` 与 stokenList 中的 `netdisk#([0-9a-f]{64})`。抽出的 BDUSS+STOKEN 调 quota/list 实测 `errno=0`。

**端点表**（★ = kernel.dll 字符串实锤，其余为 BaiduPCS-Go/社区长期验证）：

| 功能 | 端点 |
|---|---|
| 文件列表 | `GET pan.baidu.com/api/list?dir=…&order=…` |
| 搜索 | `GET pan.baidu.com/api/search?key=…&recursion=1` |
| 文件元信息/下载链 | `GET pan.baidu.com/api/filemetas?dlink=1&target=[…]`（按路径）；`GET pan.baidu.com/api/filemetas?fsids=["<fs_id>",…]&dlink=1&web=1`（按 id，一次拿回 `path`/`server_filename`/`size`/`dlink`；实测 errno=0，当前无调用方，留档备查） |
| 文件管理 | `POST pcs.baidu.com/rest/2.0/pcs/file?app_id=<PcsAppId>&method=move/copy/delete/mkdir`（同步；move/copy 为 `from`/`to` 路径对，rename 即 `from→to` 的 move） |
| 配额 | `GET pan.baidu.com/api/quota` |
| 下载 | dlink 直连（Header 带 `Cookie: BDUSS=…` + `User-Agent: netdisk`）；★ `d.pcs.baidu.com/rest/2.0/pcs/file?method=streaming`；★ `pan.baidu.com/api/download?type=batch` |
| 上传-预创建 | `POST pan.baidu.com/api/precreate`（`return_type=2` 命中即秒传）；模板变量 `GET pan.baidu.com/api/gettemplatevariable?clienttype=0&app_id=38824127&web=1&fields=["bdstoken"]` |
| 上传-分片 | ★ `{选路主机}/rest/2.0/pcs/superfile2?app_id=<PcsAppId>`（266719）；主机经 `pcs.baidu.com/rest/2.0/pcs/file?method=locateupload` 动态选路（返回主机名含 `-` 者优先）。PCS REST 端点与 pan web 端点的 app_id 不同：PCS 用 266719，pan web 端点用 250528，两者不可互换 |
| 上传-合并 | `POST pan.baidu.com/api/create` |
| 分享创建 | `POST pan.baidu.com/share/pset`（BaiduPCS-Go 同款，已实测；`share/set` 报 errno=-3） |
| 转存 | `POST pan.baidu.com/share/transfer?shareid=…&from=…&bdstoken=…&ondup=newcopy` + 表单 `fsidlist=[…]`/`path=目标父目录`（见 §4b） |
| 离线下载 | `pan.baidu.com/rest/2.0/services/cloud_dl?method=add_task / list_task` |
| 其他实锤 | ★ `pan.baidu.com/api/sharedownload`、★ `/api/batch/streaming`、★ `d.pcs.baidu.com/...?method=uploadip`（上传加速选路）、★ `cms/config?method=query`（远程配置下发，广告弹窗走这里——本项目无关，仅记录） |

**权威参考**：[BaiduPCS-Go](https://github.com/qjfoidnh/BaiduPCS-Go)（Go，接口签名/devuid/上传与转存全套，移植它的协议设计）。

## 4. 夸克网盘接口（Cookie 路线）

**无官方 API**，唯一路线。认证：浏览器登录 pan.quark.cn 后整串 Cookie 带上；接口加固定 query 参数 `pr=ucpro&fr=pc&sys=win32&uc_param_str=`，POST 均为 JSON。`sys=win32` 服务端不敏感——列目录接口带与不带均 `status=200 code=0`，实现保留该参数只为贴近客户端口径。

**Base URL**：`https://drive-pc.quark.cn/1/clouddrive/`

本项目只用到以下路径子集（未列入即未使用；`file/info`/`dir/detail`、回收站 `file/recycle/*` 已扫出但未接入）：

| 功能 | 路径 |
|---|---|
| 文件列表 | `file/sort`（GET，pdir_fid 分页） |
| 搜索 | `file/search` |
| 管理 | `file/rename`、`file/move`、`file/copy`、`file/delete`（POST） |
| 上传 | 五段式：`file/upload/pre` → `file/update/hash` → `file/upload/auth`+PUT 分片 → 合并 → `file/upload/finish`（细节见下方上传五段链） |
| 下载 | `file/download`（POST fid 列表 → 返回 download_url） |
| 会员 | `member` |
| 分享 | 创建 `share`；管理 `share/mypage/detail`、`share/delete` |
| 转存 | `share/sharepage/token` → `share/sharepage/detail` → `share/sharepage/save` |
| 扫码登录 | 四步链见下方「扫码登录链路」 |
| 任务列表 | `task/list`、`task/status` |

**扫码登录链路**（逆向自桌面客户端 login-window.js）：

1. `GET uop.quark.cn/cas/ajax/getTokenForQrcodeLogin?pr=ucpro&fr=pc&sys=win32&client_id=386&v=1.2&uc_param_str=utprfr&request_id=<uuid>` → `data.members.token`。**client_id 等参数必须带**，裸调虽也返回 token，但 token 在服务端无客户绑定，App 点确认时必报「登录请求已过期」。
2. QR 内容（不 URL 编码）：`https://su.quark.cn/4_eMHBJ?token=…&client_id=386&sch=pckk@other_ch&sve=3.24.0&ssb=weblogin&uc_param_str=&uc_biz_str=S:custom|OPT:SAREA@0|OPT:IMMERSIVE@1|OPT:BACK_BTN_STYLE@0`。用户用夸克网盘 App 扫码，端内打开「端内登录确认页」点确认。
3. 轮询 `GET uop.quark.cn/cas/ajax/getServiceTicketByQrcodeToken?<同上基础参数>&token=…`：`status=2000000` 已确认（取 `data.members.service_ticket`）、`50004001` 等待、`50004002` 二维码过期。
4. 兑换：`GET pan.quark.cn/account/info?st=<service_ticket>` → Set-Cookie 落下完整 Cookie 组（`__kp/__kps/__ktd/__uid/__pus/ctoken` 等 11 个，`_UP_` 前缀的若干个未逐一枚举），实测 `file/sort` 列目录 200。

**下载链路（含两处关键坑）**：

- `file/download` 的 `23018 download file size limit` 是 **UA 门**：官方限制 Web 端 UA 下载 100MB 以上的文件（QuarkPanTool 作者实证，SVIP 也一样受限；100MB 整这一边界值未实测），与账号会员等级无关。解法：`file/download` 请求的 UA 换成桌面客户端 UA 即解除（实测 4.5GB 文件正常返回下载链）：
  `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) quark-cloud-drive/2.5.56 Chrome/100.0.4896.160 Electron/18.3.5.12-a038f7b798 Safari/537.36 Channel/pckk_other_ch`
- 下载链（`dl-pc-zb.pds.quark.cn`）拉字节时有 OSS 回调鉴权（`drive-auth.quark.cn/outer/oss/checkplay`）：**Cookie 必须含 `__puus`**，否则 403 `require login [auth miss]`。扫码登录拿到的 Cookie 不含 `__puus`，须紧接着调一次 `GET /1/clouddrive/auth/pc/flush` 让服务端补发（此接口即会话续期口）。补发后实测 Range 206 拉字节成功 → aria2 多线程下载可行。
- `download/list` 是「生成下载清单」接口（其 download_url 是清单文件，内容形如 `/:fid;`），不是文件本体，不能用它绕限制。
- `file/search` 是 GET（不是 POST）。

**接口规格（逆向自 QuarkPanTool/QuarkPan，已实测）**：

- **通用包络**：`{status:200, code:0, message:"ok", data:{…}}`；`ThrowIfNotOk` 校验 status+code。
- **异步任务轮询**：`GET {主站}/task?task_id=<id>&retry_index=<从0递增>`；`data.status` 0待/1跑/2成/3败。move/delete/转存/创建分享都走它。
- **文件管理**（全 POST JSON）：新建 `file`（`{pdir_fid,file_name,dir_init_lock:false,dir_path:""}`→`data.fid`）、重命名 `file/rename`（`{fid,file_name}`）、移动 `file/move`（`{action_type:1,to_pdir_fid,filelist:[],exclude_fids:[]}`→`data:{task_id,finish}`，`finish=false` 轮询 task）、删除 `file/delete`（`{action_type:2,filelist:[],exclude_fids:[]}` 同轮询）。复制 `file/copy`（`{to_pdir_fid,filelist,action_type:2,copy_source:1}`，同轮询）——规格逆向自夸克桌面端 `t.copy`（3.24.0 renderer，copy_source=1）。
- **转存四步链**：① `share/sharepage/token`（`{pwd_id,passcode,support_visit_limit_private_share:true}`→`data.stoken`，pwd_id=链接 `/s/` 后段）② `share/sharepage/detail`（GET，`pwd_id/stoken/pdir_fid=0/force=0` 分页，`data.is_owner=1` 则是自己文件无需转存；每项取 `fid`+`share_fid_token`）③ `POST share/sharepage/save`（挂 `drive-pc.quark.cn`，与全量 clouddrive 端点同主机；`{fid_list,fid_token_list,to_pdir_fid,pwd_id,stoken,pdir_fid:"0",scene:"link"}`→`data.task_id`）④ 轮询 task（`data.save_as.to_pdir_name`=落地目录名）。**协议级验证**：自造分享走 SaveShare 全链被服务器正确应答（返回 `这是你自己网盘里的文件，无需转存`——服务器走到了归属判定，非协议失败）。
- **创建分享三步链**：① `POST share`（`{fid_list,title,url_type,expired_type[,passcode]}`，`url_type` 1公开/2私密，`expired_type` 永久=1/1天=2/7天=3/30天=4→`data.task_id`）② 轮询 task 取 `data.share_id` ③ `POST share/password`（`{share_id}`→`data.share_url/passcode/pwd_id`；私密链接=`share_url+"?pwd="+passcode`）。
- **分享列表**：`GET share/mypage/detail`（`_page/_size/_sort=created_at:desc`，每项 `share_id/share_url/title/first_fid/status/created_at/expired_at/file_num`）。**列表不含提取码**，要取得逐个调 `share/password`（界面不展示）。
- **删除分享**：`POST share/delete`（`{share_ids:[…]}`）。
- **上传五段链**（QuarkPan 独有，含 up 端点与 hash_ctx 算法）：`file/upload/pre`→`file/update/hash`→`file/upload/auth`+PUT `https://{bucket}.pds.quark.cn/{obj_key}?partNumber=&uploadId=`→合并 auth+POST→`file/upload/finish`。分片大小取 `pre` 响应 `metadata.part_size`（服务端下发，客户端校验须为 65536 的倍数；缺省 4MB）；`authorization` 头=auth_key；`X-Oss-Hash-Ctx`=SHA1 增量中间态（不做最终 padding 的 5 个 uint32 组 JSON 后 base64，Nl=已处理位数低 32 位、Nh=高 32 位，与桌面端 getHashCtx 一致），仅 partNumber≥2 带。秒传命中两处体现：`pre` 响应 `finish=true`（直接出结果）、`update/hash` 响应 `finish=true`（桌面端抛 FLASH_FINISH、直接用响应 data 作结果）；`repeat_backup=true` 桌面端抛 REPEAT_BACKUP（备份重复）。

**参考**：[quarkpan](https://pypi.org/project/quarkpan/)（Python，接口最干净的移植对象）、[QuarkPanTool](https://github.com/ihmily/QuarkPanTool)（转存/批量分享）、[OpenList quark 驱动](https://doc.oplist.org/)（在线预览参数参考）。

## 4b. 百度分享实测规格

- **端点**：`POST https://pan.baidu.com/share/pset`（不要用 `share/set`，它报 `errno=-3`）。
- **鉴权**：纯 Cookie（BDUSS+STOKEN），**不需要** bdstoken、不需要 query 参数。
- **表单**（`application/x-www-form-urlencoded`）：`path_list=["/路径1","/路径2"]`（按**路径**不是 fs_id）、`schannel=4`（私密）、`channel_list=[]`、`period=0`（0=永久，1/7/30=天数）、`pwd=<4位提取码>`、`share_type=9`。
- **响应**：`{errno, shareid, link, ...}`；`link` 即 `https://pan.baidu.com/s/1xxxxx`。与 `pwd` 拼 `?pwd=` 给接收方。
- **取消**：`POST share/cancel`，表单 `shareid_list=[12345]`，同样纯 Cookie 无 query。
- **无提取码的公开链接会被拒**：pwd 传空/不传即被服务端拒（BaiduPCS-Go 在客户端随机生成 4 位码后重发）。客户端策略：未指定时随机生成（去掉易混字符 ilo01）。
- 列表/改密/密码查询另有 `share/record`（GET，page/desc/order=time）、`share/surlinfo`（GET，shareid+sign）。`share/record` 已用于分享管理的列表（`ListSharesAsync`，按时间倒序逐页拉取，响应不含提取码，要查得逐个调 `share/surlinfo`，不做）；`share/surlinfo` 本项目未用，备查。
- **转存全链（实现在 src/Pandre.Core/Baidu/BaiduPanClient.cs 的 SaveShareAsync）**：
  1. 归一键：兼容 `https://pan.baidu.com/s/1xxx` 与 `share/init?surl=xxx`；`/s/` 后段缺首字符 `1` 时补上。
  2. **提取码校验**：`POST share/verify?surl=<key 去掉首字符 1>&bdstoken=<t>&t=<ms>&channel=chunlei&web=1&clienttype=0&app_id=<PanAppId>`，表单 `pwd/vcode/vcode_str`。**必须带 `Referer` 指向分享页**：无 Referer 实测 `errno=2`；`surl` 带首字符 `1` 实测 `errno=105`（`verify[surl去1+Referer]` 才 `errno=0` 并返回 `randsk`）。`randsk` 只走 **Cookie `BDCLND`**（必须手动注入 Cookie 容器）。**调校验前先删旧的 `BDCLND`**，否则上一个链接的提取码会串味。`errno=105` = 分享不存在/已失效。
  3. **分享元数据与根层文件：走接口，不解析分享页**：
     - `GET /api/shorturlinfo?shorturl=<完整 key，带首字符 1>&web=1&app_id=<PanAppId>&channel=chunlei&clienttype=0` → `shareid`（int64）+ `uk`（分享者）。**此接口 errno 即使非 0（实测 -3/-9/-21）也可能带着完整数据**，判据是字段在不在，不是 errno。
     - `GET /share/list?shorturl=<key 去掉首字符 1>&root=1&web=5&num=100&page=N&dir=%2F&channel=chunlei&app_id=<PanAppId>&clienttype=0` → `list[].fs_id`（**字符串**形态，兼容数字）。带提取码的分享必须先验过才有 `BDCLND`，否则 `errno=-9`。分页到不足 `num` 为止。
     - **页面解析法不可用**：netdisk 客户端 UA 拿到的是约 5.8KB 精简页，既无 `locals.mset` 也无文件列表；浏览器 UA 页面的内嵌字段随模板漂移。四种取法（netdisk/浏览器 UA × 带不带 Referer）都取不到 `fs_id`。
     - **注意两个 shorturl 口径相反**：`shorturlinfo` 要**完整 key**（带首字符 1），`share/list` 要**去掉首字符 1**；`share/verify` 的 `surl` 同样去掉首字符 1。
  4. **转存**：`POST share/transfer?shareid=<id>&from=<uk>&bdstoken=<t>&channel=chunlei&web=1&clienttype=0&app_id=<PanAppId>&ondup=newcopy`，表单 `fsidlist=[…]`（**根层 fs_id 逐个列出**）、`path=<目标父目录>`（目录须已存在；传目录的 fs_id 一次即递归整棵子树）。**必须带 `Referer` 指向分享页**：带上才是业务应答（自转自己：`errno=2` + `show_msg:"文件已存在"`），不带只剩 `{"errno":2,"request_id":…}` 的参数级拒绝（客户端默认 Referer 是 `disk/home`）。`ondup` 固定在 query。
  - errno 映射（实现里的用户可读文案，按链路步骤分组；拿到 errno 先看它出自哪一步，不要拿转存步骤的文案去套）：
    - **`share/verify`（提取码校验）步骤**：`-9` / `-12` 提取码错误；`105` 分享已失效或不存在；`-62` 该分享被访问次数过多、已触发百度验证，请稍后再试。
    - **`share/list`（取根层文件列表）步骤**：`-9` 该分享需要提取码（或提取码错误）；`-21` 分享已被取消或删除（`show_msg`「来晚啦，该分享已被取消」）；`140` 分享已失效或不存在；`8001` 该分享触发了百度验证，请稍后再试。
    - **`share/transfer`（转存）步骤**：`-4` / `-6` 登录态失效，请重新扫码；`-8` / `4` 目标目录已有同名文件；`-10` / `20` 网盘容量不足；`2` 参数错误或目标目录不存在（有 `show_msg` 时直接透出，如「文件已存在」）；`12` 转存文件数超限（免费号单次约 500 项）；`111` 请求过快。
    - **真网实测口径（可直接对照排查）**：无效 surl 时 `shorturlinfo` 回 `140`、`share/list` 回 `140`；`share/list` 的 surl 传空同样回 `140`；假 `shareid` 的 `share/transfer` 回 `2`。`-21` 与 `140` 属 `share/list` 这一步、不在转存这一步。`shorturlinfo` 不按 errno 判定（判据是 `shareid`/`uk` 在不在），无效链接时这两个字段一并缺失，实现报「分享链接无效或已失效」。
    - **`105` 的边界（自建分享自测自撤）**：真分享 + 错密码 = `-9`，真分享 + 对密码 = `0`（返 `randsk`），假 surl + 错密码 = `105`——`105` 专属「分享无效/不存在」，错密码走 `-9`/`-12`，实现 verify 组映射成立，排查时可直接凭 errno 定因。
  - **端到端实测**：用公开的他人分享 `https://pan.baidu.com/s/1joRvLQ7nbti0Wp4t2CkX5w`（提取码 `ZMTD`）真实转存，落盘 `【紫马课堂】课程目录.zip`（5,687,504 字节）于自建目录 `/转存验证`，随后删除文件与目录。全链 `verify(errno=0 + randsk) → shorturlinfo(shareid+uk) → share/list(errno=0) → transfer(errno=0)` 通过。另有 5 条已取消的外部分享用作 `errno=-21` 分支实测（`share/list` 的 `show_msg` 正是「来晚啦，该分享已被取消」）。
  - 附带：PCS `rest/2.0/pcs/file`（新建文件夹 `method=mkdir` 等）端点响应头写 `Content-Type: …; charset=utf8`（无连字符），.NET 的 `Encoding.GetEncoding("utf8")` 不认这个别名，`HttpClient.GetStringAsync` 直接抛 `'utf8' is not a supported encoding name`（新建文件夹会因此必失败）。已在 `src/Pandre.Core/PanHttp.cs` 的 HTTP 管道里用 `CharsetFixHandler` 统一归一 charset，两盘共用，调用点不必各自兜底。

## 4c. 百度秒传链接：三条通道的判决（结论=不可用）

测试对象用**公开样例**（非自有文件），以排除「服务端不认识这个哈希」的干扰：`md5=d5aabefc3290f7a3c09912228b136d0c`、`slice-md5=821a9f0d27fcd19c80474d2140ed2d85`、`size=6467659`、`name=test.exe`（`rapid-upload-userscript-doc` 文档里的标准样例）。

| 通道 | 请求 | 实测结果 |
|---|---|---|
| A. v1 `/api/rapidupload` | `POST pan.baidu.com/api/rapidupload?app_id=250528&bdstoken=…&channel=chunlei&clienttype=0&rtype=1&web=1`，表单 `path/content-md5/slice-md5/content-length` | **全矩阵 `errno=2`**：浏览器 UA / netdisk UA / +Referer / +X-Requested-With / 去掉 bdstoken / md5 大小写，全部一样。UA 变体已排除「缺 UA 即报 errno=2」这一服务端原因 |
| B. v2 minimal precreate | `POST pan.baidu.com/api/precreate`，`block_list=["<content-md5>"]` + `autoinit=1`，`rtype` 2 / 3 各试 | 两者都回 `return_type=1`（= 要求真传），`block_list:[0]`。原因：`block_list` 要的是**按 4MB 分片的逐块 md5 表**，单元素整文件 md5 对不上（>4MB 的文件必然失配） |
| C. 古典 PCS | `POST pcs.baidu.com/rest/2.0/pcs/file?method=rapidupload&app_id=266719` + Cookie | `{"error_code":31045,"error_msg":"user not exists"}`——PCS 端点认 **OAuth access_token** 身份，Cookie 会话无效 |

**根因**：bdpan:// 链接只携带 `content-md5` + `slice-md5`，而当前唯一可用的服务端校验入口是 precreate，它要求逐块 md5 表；逐块 md5 无法由整文件 md5 与首 256KB 切片 md5 反推。v1 端点对 Cookie 会话不可用，古典 PCS 端点只认 access_token。故产品侧不做秒传导入。

- 上传链路的秒传命中（`src/Pandre.Core/Baidu/BaiduPanClient.cs` 的 `UploadAsync`，precreate 传真实逐块 md5 表，`return_type=2`）**不受影响**，工作正常。
- `src/Pandre.Core/Baidu/BaiduPanClient.cs` 的 `UploadAsync` 注释里「秒传 data_offset 依赖」的 uk 取值仍然需要（上传预创建要用），保留。
- **`filemetas` 返回的 md5 对大文件普遍是脏值**（实测拿到过含字母 `o` 的 `0c4693b17od4c9aa34876e7b83536502`）；dlink 带 `Range` 请求的响应也**没有 `Content-MD5` 头**。即「从盘上已有文件反推签名」这条取数路子也不通。

## 5. 技术栈与工程约定

- **.NET 10 LTS + Avalonia UI（Fluent 主题）**，MVVM 用 `CommunityToolkit.Mvvm`。需要 .NET 10 SDK。
- **跨平台**：Windows + macOS + Linux 三平台，发布节奏 Windows 先行 → macOS/Linux 标 beta。选 Avalonia 的理由：保住「纯 C# 直连」核心决策，协议层零改动；Fluent 主题外观接近 WinUI。Android 明确不做（维护成本不成比例）。macOS 无开发者证书，发布说明里注明用户右键打开（开源项目可申请 SignPath 免费签名）。
- 下载引擎：Windows 内嵌 **aria2c** 官方二进制子进程（成熟的多线程/断点续传），不要自己造轮子。**macOS/Linux 的下载方案需要另行定夺**——aria2 官方只发 Windows 包，届时在「第三方预编译（需校验哈希）/ 用户自装 / 自写 C# 下载器」中按实况三选一。发布包须附带 aria2 的 GPL-2.0 许可证文本（子进程聚合分发，不传染本项目许可证）。
- **引擎生命周期与失效语义**：轮询每秒检测子进程存活，发现 `aria2c` 已退出就自动重新拉起（`DownloadManager.PollLoopAsync` 的 `_engine.IsAlive` 分支，带启动闸防并发重入）；队列是 aria2 的内存态，重启后旧 gid 全部失效，此时仍处活跃态（排队/下载中/已暂停）的任务行会转成 Error 并给出「与下载引擎失去联系（引擎重启或结果被清理）」，不会冻结在「下载中」。断点续传靠 aria2 自己落的 `.aria2` 控制文件，所以用户重新添加同一链接即可从断点续传。
- **RPC 鉴权的可见边界**：`rpc-secret` 是每次启动随机生成的十六进制串，以命令行的 `--rpc-secret=<值>` 形式传给子进程，**同机同用户的其它进程可以读到该命令行**（`CreateProcess` 的命令行对同用户进程可见）。缓解是三重叠加——secret 每次启动更换、`--rpc-listen-all=false` 只监听回环、端口随机；aria2 没有 secret-file 通道，不改运行时行为的前提下无法消除这一可见性。
- 打包：各平台单文件自包含，绿色免安装。**不写注册表、不加右键菜单、不进「此电脑」、不开机自启**——这是设计规范，不是可选项。
- **Cookie 落盘**（BDUSS 等于百度全站通行证）：Windows 用 DPAPI（当前用户）加密；非 Windows 明文 JSON 加文件权限 0600，非 Windows 的 Keychain / libsecret 接入后替换该明文存储。
- **网络**：应用自身的 HTTP 请求（网盘接口）跟随系统代理；**下载引擎不继承系统代理、也不走 IPv6**——`Aria2Engine.SpawnProcess` 启动子进程时删除 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` 环境变量并加 `--disable-ipv6=true`。原因：aria2 会读前两个环境变量，`--split=16` 的下载全部挤过本地代理会掉速且 WinTLS 并发握手随机失败；百度下载域名 `d.pcs.baidu.com` 的 DNS 同时返回 AAAA 与 A，在无 IPv6 出口的网络上 aria2 一旦选中 AAAA 就立即以 `unreachable network` 失败且不回退 IPv4。验证方式：应用内 aria2 的 `aria2.getGlobalOption` 应回报 `disable-ipv6=true`，且 `all-proxy` / `http-proxy` / `https-proxy` 三项均不存在。不做应用内代理开关。零遥测：代码里不存在任何统计/上报 SDK。
- 更新机制：设置页放「检查更新」按钮跳 GitHub Release，不做自动下载替换（避免杀软误报）。
- 实际目录结构：

```
Pandre.slnx
  src/Pandre.Core/        # 无 UI 依赖：模型、接口抽象 IPanClient、凭据、HTTP
    Baidu/  Quark/
  src/Pandre.Download/    # aria2 封装、队列、断点续传
  src/Pandre.Desktop/     # Avalonia 壳（Windows 先行）：Views/ViewModels
```

- 接口抽象先行：`IPanClient`（List/Search/Rename/Move/Copy/Delete/Download/Upload/Share/SaveShare/OfflineDownload），两家各自实现，UI 只面向抽象。
- **异步纪律**：可能被同步等待（`GetAwaiter().GetResult()`）的库方法，内部 await 一律 `ConfigureAwait(false)`。`Aria2Engine.CallAsync` 若捕获 Avalonia UI 同步上下文，启动时续体要回 UI 线程而 UI 线程正阻塞等它，即**死锁**：进程活着、`Responding=True`、aria2c 已起，主窗口创建了却永不显示（枚举进程窗口 `vis=False`，无 .NET 崩溃日志）。引擎启动放线程池（`Task.Run`）与登录恢复并行。**E2E 验收必须走真实 app 路径**，控制台直接 new `DownloadManager` 测不到启动链断裂。

## 6. 桌面端 UI 结构（Avalonia 12.1.4 实况）

窗口外观：`ExtendClientAreaToDecorationsHint=True` + `TransparencyLevelHint="Mica, AcrylicBlur"` + `Background=Transparent`，无边框自绘标题栏高度 40 DIP。

- **WindowDecorations 必须用 `BorderOnly`**。Avalonia 12 的 `Window.WindowDecorations` 是枚举 `None / BorderOnly / Full`（默认 Full）。Full 由装饰层自绘标题带：整窗宽、高 40 DIP、**不透明**（装饰模板内部元素不可达，`Button#PART_FullScreenButton` 这类样式能命中按钮，但标题带容器按类型/名字都改不动底色），深色主题下呈现纯黑 `rgb(0,0,0)`，覆盖侧栏与内容列；且 Full 自带窗口图标与最小化/最大化/关闭/全屏四个按钮，全屏键多余。`BorderOnly` 下装饰层只画边框/阴影/缩放手柄，标题带全部由应用内容决定，Mica 直接透出，与主体同材质（实测标题带采样 `rgb(32,32,32)`，与主体一致）。
- **窗口按钮自绘**：标题行右侧 StackPanel，`Button.caption` 46×40、圆角 0、关闭键 hover `#C42B1C`；最大化/还原图标随 `WindowStateProperty` 的 `PropertyChanged` 切换；窗口拖动由 `TitleDragArea` 的 `PointerPressed → BeginMoveDrag`。最小化/最大化/还原/关闭、右边缘拖拽缩放（+120px）均实测通过，圆角与系统阴影保留。
- **托盘图标 + 关闭按钮行为**：
  - 挂载点是 **`Application` 上的附加属性**：`App.axaml` 里写 `<TrayIcon.Icons><TrayIcons><TrayIcon Icon="/Assets/pandre.ico" ToolTipText="盘多录 Pandre" Clicked="OnTrayIconClicked">…`，即 `TrayIcon.SetIcons(Application, TrayIcons)`（反射实测签名 `SetIcons(Application o, TrayIcons trayIcons)`；`Application` 本身**没有** `TrayIcons` 属性，别去找）。`TrayIcon.Icon` 是 `WindowIcon`，`Menu` 是 `NativeMenu`。
  - 关闭行为由设置项 `CloseBehavior`（`exit` / `tray`，默认 `tray`）决定，落地在 `Services/TrayService.cs` + `MainWindow.OnClosing`：`ShouldHideOnClose` 为真时 `e.Cancel = true; Hide();`（隐藏而非关闭，窗口从任务栏消失、进程存活、下载继续）；托盘菜单「退出应用」先置 `TrayService.ExitRequested` 再 `Close()`，走正常退出分支，`Application.Exit` 里照旧收尾 aria2 与两个客户端。托盘左键单击 = 唤回主窗口。
  - 实测（UIA + `CloseMainWindow()`）：发 WM_CLOSE 后进程存活、顶层窗口从 UIA 树消失即隐藏成功；**不要用 `IsWindowVisible` 判断**（本应用窗口恒为 `False`，不可靠）。
  - 设置页对应行在「个性化」卡：`关闭按钮行为` / `点击标题栏关闭按钮时执行的操作`，下拉 `退出应用` / `最小化到托盘`。
- **已失效写法（AVLN2000）**：`ExtendClientAreaChromeHints`（Avalonia 12 已移除）。`SystemDecorations=None` 会让拖动缩放失效（实测 `resized=False`），不要用它换无边框。
- 侧栏用 `Grid.RowSpan="2"` 贯通整窗高度（含标题行），logo 在顶部、导航紧随；不要再给侧栏单独留 Row 0 占位。内容列自己的标题行只放拖拽区与窗口按钮。
- 登录伪弹窗 `LoginOverlay` 必须 `Grid.RowSpan="2" Grid.ColumnSpan="2"`。外层 Grid 是「72px 侧栏 + 内容」两列，漏写 ColumnSpan 时遮罩会被压进 72px 侧栏列（卡片被裁成一条）。
- **网盘操作弹窗挂窗口级，不挂 PanView 级**。弹窗 Grid 放进 `PanView.axaml` 时遮罩只压暗内容区、侧栏和标题栏仍亮着。现行做法：`MainWindow.axaml` 根部放 `Grid RowSpan=2 ColumnSpan=2 ZIndex=30 IsVisible={Binding IsPanDialogOpen}`，这个 Grid 的 DataContext 就是窗口的 `MainViewModel`，遮罩 `Border` 在其下并直接用该 DataContext；只有卡片层 `Border` 才挂 `DataContext={Binding CurrentPan} x:DataType=vm:PanViewModel`。`MainViewModel.CurrentPan => CurrentPage as PanViewModel`（`OnCurrentPageChanged` 里 `OnPropertyChanged`），可见性走单独的 `IsPanDialogOpen => CurrentPan is { IsDialogOpen: true }`。**可见性必须绑这个可空安全的计算属性，不能写成 `IsVisible={Binding CurrentPan.IsDialogOpen}`**：非网盘页 `CurrentPan` 是 null，再取子属性得到的是 `UnsetValue` 而不是 false，`IsVisible` 随之回落到属性默认值 `true`，遮罩会在非网盘页恒显、点遮罩也关不掉（点遮罩的处理要先判 `CurrentPan != null`，为 null 时静默失效）。处理器在 `MainWindow.axaml.cs`：`OnPanDialogScrimPressed` 从窗口的 `MainViewModel` 取 `CurrentPan` 再 `DialogCancelCommand.Execute(null)`；`OnCopyPanDialogTextClick` 的 sender 在卡片内，DataContext 是 `PanViewModel`。`PanView` 里只剩工具栏与文件列表。切页时 `OnSelectedNavChanged` 对两侧 `DialogCancelCommand.Execute(null)` 兜底关弹窗；`Esc` 先关登录弹窗再关网盘弹窗。
- **XAML 处理器漏写的增量构建陷阱**：`.axaml` 里 `PointerPressed="X"` 但 code-behind 没有 `X` 时，`dotnet build` 只在**全量** XAML 编译时报 `AVLN3000`；增量构建会跳过报错、产出缺预编译 XAML 的程序集，运行期才抛 `XamlLoadException: No precompiled XAML found for Pandre.Desktop.App`。**改 XAML 后见到 XamlLoadException 先 `Remove-Item obj,bin` 全量重建**，别信增量构建的「0 错误」。
- 果冻指示条：位置由代码后置实测 ListBox 项的 `TranslatePoint` 求出（写 `NavIndicator.Margin` 左边距 + `RenderTransform translateY`），首次落位不动画，之后挂 `TransformOperationsTransition` 420ms（自写 `SoftBackEaseOut`，默认过冲 3.5%）+ `Height` 200ms `CubicEaseOut` 脉冲（20 → 最远 38，距离越远拉得越长）。**必须在 `NavArea.SizeChanged` 上「摘过渡、瞬时跟位」重算**：位移是按导航区高度算的，窗口缩放后沿用旧值会让指示条飘到窗口顶部。
- 页面切换 `ConnectedFadeTransition`：旧页 150ms `SineEaseOut` 淡出，新页从下方 20px 起 300ms `CubicEaseOut` 淡入上浮。
- 行悬浮不做位移（`Border.row-card` 无 BoxShadow/RenderTransform），只换背景色，避免上浮被裁切。
- **次要/辅助文字对比度（勿回退）**：现值——深色主题卡片 `#0DFFFFFF` 叠加 `#202020`（实测渲染 42/43 = `#2B2B2B`），其上 `TextTertiaryBrush #B8B8B8`（7.1:1）、`TextSecondaryBrush #D6D6D6`（9.7:1）；浅色主题卡底 `#FDFDFD`，`TextTertiaryBrush #6E6E6E`（5.0:1）、`TextSecondaryBrush #5A5A5A`（6.8:1）；`TextBlock.tertiary` 字号 12。**下限是 WCAG AA 4.5:1**——低于此值时字太灰、不可读。抽样验证法：截图后取区域内「最亮近灰像素」，实测时间列 184、`共 N 项` 214、卡片底 75/76，与资源值一致。
- 下载目录行 = TextBox（MinWidth 320）+ `Button Content="浏览…" Click="OnBrowseDownloadDir"`；处理器走 `TopLevel.GetTopLevel(this)?.StorageProvider.OpenFolderPickerAsync(...)`，取 `folders.FirstOrDefault()?.TryGetLocalPath()` 写回 `SettingsViewModel.DownloadDir`（由其 `OnDownloadDirChanged` 持久化），不直接碰配置文件。
- 侧栏几何：侧栏 `Border` 是 `Grid.RowSpan="2"`（贯通标题行），`NavArea` 为 `Grid.Row="1" Margin="0,8,0,0"`，logo `Border Margin="0,14,0,4"`。实测百度项背景顶边 y=66px（标题带 40 DIP 之下），logo 强调色包围盒中心 y≈34px（需落在「窗口顶 → 百度项顶」的中点 33px 附近）。导航项位置随这两处 Margin 联动，改一侧必须同额抵消另一侧，否则导航整体位移。
- **控件观感对齐 Win11（勿回退）**：Avalonia 12.1.4 自带 Fluent 主题的默认资源是 Win10 世代——`ComboBoxBorderBrush`/`TextControlBorderBrush` 指向 `SystemControlForegroundBaseMediumBrush`（深色 = 60% 白，实测边框渲染 177 = #B1B1B1，刺眼）；`ButtonBackground` 指向 `SystemControlBackgroundBaseLowBrush`（实测按钮底渲染 111，过亮）；`ControlCornerRadius=3`；`CardBrush` 是 20% 白渲染 #4C4C4C（Win11 设置卡是 #2B2B2B）。**覆盖方法**：控件模板用 `{DynamicResource 别名键}` 查找，在 App.axaml 的 ThemeDictionaries 里重定义同名别名键即优先生效（无需改主题文件）。现值——深色：边框 `#14FFFFFF`（hover `#26FFFFFF` / pressed `#1AFFFFFF`）、按钮底 `#0FFFFFFF`（hover `#15FFFFFF` / pressed `#08FFFFFF`）；浅色：边框 `#29000000`（hover `#47000000`）、按钮 `#0F000000` 系列；`ControlCornerRadius` 4（外层字典，双主题共用）；深色卡片 `#0DFFFFFF`（实测渲染 42/43 = #2B2B2B）、`ThumbBgBrush #333333`。焦点态边框仍走主题自带的强调色（`TextControlBorderBrushFocused`），不要覆盖。别名键与 SystemControl* 的映射见官方源码 `src/Avalonia.Themes.Fluent/Accents/FluentControlResources.xaml`（release/12.1.4）。

- **图标（勿自造）**：图形资产都在 `assets/icons/`，命名固定：
  - `pandre-app.svg` — 应用标识，**256 格**坐标：弓形单边翅膀 + 中央单枚大水晶（水晶的竖直中线即画布竖直中线，无需额外对齐）。
  - `pandre-app-hollow.svg` — 同一标识的**镂空版**（水晶只描边不填充），**256 格**坐标，用于设置页「关于」卡（深浅两主题通用）：侧栏 logo 用实心版，关于卡用镂空版以免 20px 下实心色块过重。
  - `pandre-app-icon.svg` — **应用图标成品源**，**48 格**坐标（Win11 应用图标基准网格）：`squircle` 底板 + 120° 环境光渐变 + 纯白标记，是 `pandre.ico` **48 帧及以上（48/64/128/256）的渲染源**；标记几何与 `pandre-app.svg` 同源（按底板宽 70% 居中摆正，变换 `translate(5.226,2.733) scale(0.14667)`）。规范自检：`python <fluent-icon-creator>/scripts/check-fluent-icon.py assets/icons/pandre-app-icon.svg --type app` → PASS（0 错 0 警）。
  - `pandre-app-icon-small.svg` — **小尺寸满幅版**，**48 格**坐标、底板占满 48×48（不留边）：位图小尺寸没有系统留边，满幅才能与系统图标等大。**`pandre.ico` 的 16/24/32 帧来自这一份**，任务栏与托盘按这几帧渲染。
  - `icon-baidu.svg` / `icon-quark.svg` — 两个网盘的品牌图标，**24 格**坐标，与 `Icons.cs` 里的 Fluent 图标同视口，可混排。
  - `*.flat.svg` — 四份设计稿 `pandre-app.svg` / `pandre-app-hollow.svg` / `icon-baidu.svg` / `icon-quark.svg` 各有一份对应的「填充展开稿」：`pandre-app.flat.svg` / `pandre-app-hollow.flat.svg` / `icon-baidu.flat.svg` / `icon-quark.flat.svg`。设计原稿是描边（stroke）图形，展开稿把每条描边摊成填充轮廓后取并集，得到单条无自交 path（EvenOdd 与 Nonzero 下渲染一致）。两份图标成品源本身是填充图形，没有展开稿。展开稿与 `src/Pandre.Desktop/Icons.Brand.cs` 里的常量**逐字符相同**，是比对的基准。
  - 代码里的常量在 `src/Pandre.Desktop/Icons.Brand.cs`（`AppIcons.PandreMark` / `PandreMarkHollow` / `BaiduNetdisk` / `QuarkNetdisk`）；`Icons.cs` 与它是同一个 `partial class AppIcons`，前者放 Fluent 界面图标（MIT），后者放**这四个**品牌图形——`PandreMark`（实心，侧栏 logo）、`PandreMarkHollow`（镂空，设置页「关于」卡）、`BaiduNetdisk` / `QuarkNetdisk`（两个网盘图标）。
  - 界面接法：侧栏顶部 logo 用 `Viewbox Width=26 Height=26` + `Path Data`（因为 `PandreMark` 是 256 格坐标，必须靠 Viewbox 缩放，`PathIcon` 不行）；导航项与登录卡片标题用 `PathIcon`（24 格，和 Fluent 图标同规格）。**品牌图标是单色单形态，选中态不换图标**——靠背板强调色与左侧指示条表达当前页（Fluent 那两枚才有 Regular/Filled 两版）。
  - **窗口/任务栏图标**：`src/Pandre.Desktop/Assets/pandre.ico`，7 帧（16/24/32/48/64/128/256），16–128 帧为 32bpp BMP 帧、256 帧为 PNG 帧——这条混排不是随意选的：只写 PNG 帧时 Windows 的 GDI+ 取图路径会整份忽略该文件，只写 BMP 帧则 256 帧体积过大且部分老组件读不了。**帧来源分两段**：48/64/128/256 帧由 `pandre-app-icon.svg` 渲出，16/24/32 帧由 `pandre-app-icon-small.svg` 渲出（满幅无留边）。任务栏与 alt-tab 走应用图标，因此 csproj 里同时设了 `<ApplicationIcon>Assets\pandre.ico</ApplicationIcon>`（进 exe 的资源节）与 `MainWindow` 的 `Icon="/Assets/pandre.ico"`（窗口图标），**两处都要**，只设一处会出现「窗口标题栏有图标、资源管理器里没有」。托盘图标共用同一个 `.ico`（`App.axaml` 的 `TrayIcon.Icon="/Assets/pandre.ico"`，Win11 通知区域按 16px 帧渲染），改一处即三处同步。
  - 底图规格：**绯红渐变**超椭圆方角卡（squircle，指数 4.6，四周留 8/256 边距），渐变 `#FF6B6B → #C81E1E`、取 120° 环境光方向，图形按实测包围盒缩放进卡宽 70% 的安全区并自动居中。之所以用 squircle 而非普通圆角矩形：Win11 系统图标底板是连续曲率方角，普通圆角矩形在 32px 下明显更尖。**底板必须用饱和色，不能用中性暗底**：深色任务栏底色约 `#202020`，中性暗底与它明度几乎相同，托盘与任务栏上只剩白色标记浮着、整体轮廓糊掉；饱和色底板在明度与色相两个维度同时拉开，实测 16px 帧仍清晰、深浅两种任务栏下都醒目。
- **强调色跟随 Windows 系统强调色**：`src/Pandre.Desktop/Services/AccentService.cs` 在启动时读 `Application.Current.PlatformSettings.GetColorValues().AccentColor1`（与注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Accent\AccentColorMenu` 同值），写进 App.axaml 两层 `ThemeDictionaries` 的同名键 `AccentColor` / `AccentBrush` / `NavSelectedBrush` / `OnAccentBrush`，并写 `FluentTheme.Palettes[Dark|Light].Accent`（Fluent 内建控件的强调色取自这里）；系统换色时经 `PlatformSettings.ColorValuesChanged` 重写一次。**必须写进主题字典而不是顶层键**——顶层键会遮蔽主题字典键，写成顶层就只有一套颜色、深浅主题不再分开。
  - **可读性下限**：系统色在该主题底色（深 `#202020` / 浅 `#FFFFFF`）上不足 WCAG 4.5:1 时，只沿 HSL 明度轴推到刚好达标，色相与饱和度不动。以中性灰 `#A1A1A1` 为例：深色底 6.30:1 达标、原值照用；浅色底只有 2.58:1，推到 `#767676`（4.54:1）。
  - `OnAccentBrush` 压在强调色实底上的前景，黑/白取对比度高者；`App.axaml` 的 `Button.primary` 用它，不要写死 `White`（强调色可变之后，浅色底上的 `#767676` 实底配白字只有 4.54:1、配黑字 4.62:1）。
  - 实测四处：主按钮实底浅色 `#767676` / 深色 `#A1A1A1`（前景均取黑）；Fluent 勾选框选中态填充 `#767676`（证明 `Palettes` 生效）；运行期改写主题字典后侧栏选中态与 logo 立即变色（`DynamicResource` 已解析的也会跟着刷新，换色不需要重启）。
