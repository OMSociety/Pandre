## 2. 架构决策（研究结论，勿推翻重来）

**选型：纯 C# 直连两家 Cookie 接口。已否决「WinUI3 壳 + 内嵌 OpenList 后端」方案**，理由：背一个 Go 本地服务器、体验上限被 OpenList API 封死、百度驱动依赖祖传共享密钥随时可能失效。

**为什么走网页 Cookie 接口而不是复刻桌面端协议**（逆向取证证据）：

- 两家 PC 客户端都是 Electron 套壳。百度网盘 8.8.8：`module\BrowserEngine\resources\app.asar`（226 MB，package.json 显示 `@baidu/disk-core` 等内部包）；夸克网盘 3.24.0：`app-3.24.0\resources\app.asar`（126.6 MB）。
- 夸克客户端带 `SecurityGuardSDK64.dll`（阿里聚安全）+ `UTDID.dll`，**桌面端私有请求有设备指纹签名层**，复刻成本高且容易触发风控；网页接口（`drive-pc.quark.cn`）只需 Cookie，已被 quarkpan / QuarkPanTool / OpenList 驱动长期验证。
- 百度客户端的协议栈在 native 层 `kernel.dll`（42 MB），JS 壳里几乎没有接口路径。对 kernel.dll 做了字符串提取（非反汇编），实锤端点见下表，与 BaiduPCS-Go 源码相互印证。

**开发者的两个疑问（2026-10-13 已决）**：「网页版功能比桌面版少，Cookie 够吗」——够。本文档两张端点表已覆盖第 1 节「要做」的全部功能；桌面端多出来的同步空间、相册备份本就在「先不做」清单里。「扫码登录怎么样」——扫码与 Cookie 路线不矛盾，扫码就是拿 Cookie 的手段。产品登录只做扫码，不做手动粘贴（见 §6）。两家扫码链路均已在 P0.5 实测跑通（细节见 §3/§4）。注：`quark-api-paths.txt` 第 10、58 行的 `auth/pc/flush`、`distribute/act/pc/login/take` 曾被认为是扫码端点，P0.5 已证伪：flush 是刷新 `__pus/__puus` 的 Cookie 续期接口，take 实为领奖接口（postPcLoginAward）；真扫码链路在 `uop.quark.cn/cas/ajax/` 下。


**两个 asar 解包树保留在本地**（需要查接口细节时直接 grep）：

- `D:\WorkSpace\WorkBench\pan-re\baidu-asar\`
- `D:\WorkSpace\WorkBench\pan-re\quark-asar\`
- 端点扫描产物：`endpoints-hosts.txt`（544 条）、`quark-api-paths.txt`（161 条全量）、`baidu-kernel-strings.txt`（38 条），同目录下。

## 3. 百度网盘接口（Cookie 路线）

**为什么不用官方开放平台**：新申请应用只能访问 `/apps/<应用名>` 单一目录，全盘权限基本不批；个人开发者拿不到分享 API。

**认证**：浏览器登录 pan.baidu.com 后取 Cookie `BDUSS` + `STOKEN`；部分接口需要 `devuid`（设备标识，BaiduPCS-Go 有生成算法）。

**扫码登录链路（2026-10-13 P0.5 实测全绿）**：

1. `GET passport.baidu.com/v2/api/getqrcode?lp=pc` → `sign` + `imgurl`（imgurl 无 scheme，需补 `https://`）。
2. 长轮询 `GET passport.baidu.com/channel/unicast?channel_id={sign}&…`：`channel_v` 里 `status=1` 已扫码、`status=0` 已确认并给出 `v`。
3. `GET passport.baidu.com/v3/login/main/qrbdusslogin?…&v=…` → 返回 200 伪 JSON（单引号 + `&quot;` 转义）。**坑：Set-Cookie 里的 BDUSS 对 pan.baidu.com 无效**（quota 400、disk/main 302 回登录页）；真凭证在响应体 `session` 字段里，须正则抽取 `"bduss":"([^"]+)"` 与 stokenList 中的 `netdisk#([0-9a-f]{64})`。抽出的 BDUSS+STOKEN 调 quota/list 实测 `errno=0`。

**端点表**（★ = kernel.dll 字符串实锤，其余为 BaiduPCS-Go/社区长期验证）：

| 功能 | 端点 |
|---|---|
| 文件列表 | `GET pan.baidu.com/api/list?dir=…&order=…` |
| 搜索 | `GET pan.baidu.com/api/search?key=…&recursion=1` |
| 文件元信息/下载链 | `GET pan.baidu.com/api/filemetas?dlink=1&target=[…]`（按路径）；`GET pan.baidu.com/api/filemetas?fsids=["<fs_id>",…]&dlink=1&web=1`（按 id，一次拿回 `path`/`server_filename`/`size`/`dlink`，浏览器接管入口用它把网页选中的文件直接变成下载任务） |
| 文件管理 | `POST pan.baidu.com/api/filemanager?opera=rename/move/copy/delete`（异步任务） |
| 配额 | `GET pan.baidu.com/api/quota` |
| 下载 | dlink 直连（Header 带 `Cookie: BDUSS=…` + `User-Agent: netdisk`）；★ `d.pcs.baidu.com/rest/2.0/pcs/file?method=streaming`；★ `pan.baidu.com/api/download?type=batch` |
| 上传-预创建 | `POST pan.baidu.com/api/precreate`（`return_type=2` 命中即秒传）；模板变量 `GET pan.baidu.com/api/gettemplatevariable?clienttype=0&app_id=38824127&web=1&fields=["bdstoken"]` |
| 上传-分片 | ★ `c.pcs.baidu.com/rest/2.0/pcs/file?method=upload&type=tmpfile`，`app_id=250528` |
| 上传-合并 | `POST pan.baidu.com/api/create`；大文件走 ★ `/rest/2.0/pcs/superfile2` |
| 分享创建 | `POST pan.baidu.com/share/pset`（BaiduPCS-Go 同款，已实测）；旧文档 `share/set` 报 errno=-3 |
| 转存 | `POST pan.baidu.com/share/transfer?shareid=…&from=…&bdstoken=…&ondup=newcopy` + 表单 `fsidlist=[…]`/`path=目标父目录`（已实现，见 §4b） |
| 离线下载 | `pan.baidu.com/rest/2.0/services/cloud_dl?method=add_task / query_task` |
| 其他实锤 | ★ `pan.baidu.com/api/sharedownload`、★ `/api/batch/streaming`、★ `d.pcs.baidu.com/...?method=uploadip`（上传加速选路）、★ `cms/config?method=query`（远程配置下发，广告弹窗走这里——本项目无关，仅记录） |

**权威参考**：[BaiduPCS-Go](https://github.com/qjfoidnh/BaiduPCS-Go)（Go，接口签名/devuid/上传与转存全套，移植它的协议设计）。

## 4. 夸克网盘接口（Cookie 路线）

**无官方 API**，唯一路线。认证：浏览器登录 pan.quark.cn 后整串 Cookie 带上；接口加固定 query 参数 `pr=ucpro&fr=pc&uc_param_str=`，POST 均为 JSON。

**Base URL**：`https://drive-pc.quark.cn/1/clouddrive/`

从客户端 3.24.0 的 asar 里扫出 161 条路径（全量见 `quark-api-paths.txt`），本项目用到的子集：

| 功能 | 路径 |
|---|---|
| 文件列表 | `file/sort`（GET，pdir_fid 分页） |
| 搜索 | `file/search`、`file/general_search` |
| 详情 | `file/info`、`dir/detail` |
| 管理 | `file/rename`、`file/move`、`file/copy`、`file/delete`（POST） |
| 回收站 | `file/recycle/list` / `recover` / `remove` |
| 上传 | 五段式：`file/upload/pre` → `file/update/hash` → `file/upload/auth`+PUT 分片 → 合并 → `file/upload/finish`（细节见 §4 上传五段链） |
| 下载 | `file/download`（POST fid 列表 → 返回 download_url） |
| 配额/会员 | `quota/use`、`quota/remain`、`member` |
| 分享 | 创建 `share`；管理 `share/mypage/detail`、`share/delete` |
| 转存 | `share/sharepage/token` → `share/sharepage/detail` → `share/sharepage/save` |
| 扫码登录（P0.5 已实测跑通） | 四步链见下方「扫码登录链路」 |
| 任务列表 | `task/list`、`task/status` |

**扫码登录链路（2026-10-13 P0.5 实测全绿，逆向自桌面客户端 login-window.js）**：

1. `GET uop.quark.cn/cas/ajax/getTokenForQrcodeLogin?pr=ucpro&fr=pc&sys=win32&client_id=386&v=1.2&uc_param_str=utprfr&request_id=<uuid>` → `data.members.token`。**client_id 等参数必须带**，裸调虽也返回 token，但 token 在服务端无客户绑定，App 点确认时必报「登录请求已过期」（踩过此坑）。
2. QR 内容（不 URL 编码）：`https://su.quark.cn/4_eMHBJ?token=…&client_id=386&sch=pckk@other_ch&sve=3.24.0&ssb=weblogin&uc_param_str=&uc_biz_str=S:custom|OPT:SAREA@0|OPT:IMMERSIVE@1|OPT:BACK_BTN_STYLE@0`。用户用夸克网盘 App 扫码，端内打开「端内登录确认页」点确认。
3. 轮询 `GET uop.quark.cn/cas/ajax/getServiceTicketByQrcodeToken?<同上基础参数>&token=…`：`status=2000000` 已确认（取 `data.members.service_ticket`）、`50004001` 等待、`50004002` 二维码过期。
4. 兑换：`GET pan.quark.cn/account/info?st=<service_ticket>` → Set-Cookie 落下完整 Cookie 组（`__kp/__kps/__ktd/__uid/__pus/ctoken` 等 11 个，`_UP_` 前缀的若干个未逐一枚举），实测 `file/sort` 列目录 200。

**下载链路（2026-10-13 实测全通，含两处关键坑）**：

- `file/download` 的 `23018 download file size limit` 是 **UA 门**：官方限制 Web 端 UA 下载 100MB 以上的文件（QuarkPanTool 作者实证，SVIP 也一样受限；100MB 整这一边界值未实测），与账号会员等级无关。解法：`file/download` 请求的 UA 换成桌面客户端 UA 即解除（实测 4.5GB 文件正常返回下载链）：
  `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) quark-cloud-drive/2.5.56 Chrome/100.0.4896.160 Electron/18.3.5.12-a038f7b798 Safari/537.36 Channel/pckk_other_ch`
- 下载链（`dl-pc-zb.pds.quark.cn`）拉字节时有 OSS 回调鉴权（`drive-auth.quark.cn/outer/oss/checkplay`）：**Cookie 必须含 `__puus`**，否则 403 `require login [auth miss]`。扫码登录拿到的 Cookie 不含 `__puus`，须紧接着调一次 `GET /1/clouddrive/auth/pc/flush` 让服务端补发（此接口即会话续期口，原 asar 里 `auth/pc/flush` 的真实用途）。补发后实测 Range 206 拉字节成功 → aria2 多线程下载可行。
- `download/list` 是「生成下载清单」接口（其 download_url 是清单文件，内容形如 `/:fid;`），不是文件本体，不能用它绕限制。
- `file/search` 是 GET（不是 POST）；`quota/use` 是 POST（不是 GET）。

**P2 接口规格（2026-10-14 逆向自 QuarkPanTool/QuarkPan，阶段1已实测；转存链路协议级验证通过，外部分享链接验收待用户提供）**：

- **通用包络**：`{status:200, code:0, message:"ok", data:{…}}`；`ThrowIfNotOk` 校验 status+code。
- **异步任务轮询**：`GET {主站}/task?task_id=<id>&retry_index=<从0递增>`；`data.status` 0待/1跑/2成/3败。move/delete/转存/创建分享都走它。
- **文件管理**（全 POST JSON）：新建 `file`（`{pdir_fid,file_name,dir_init_lock:false,dir_path:""}`→`data.fid`）、重命名 `file/rename`（`{fid,file_name}`）、移动 `file/move`（`{action_type:1,to_pdir_fid,filelist:[],exclude_fids:[]}`→`data:{task_id,finish}`，`finish=false` 轮询 task）、删除 `file/delete`（`{action_type:2,filelist:[],exclude_fids:[]}` 同轮询）。复制 `file/copy`（`{to_pdir_fid,filelist,action_type:2,copy_source:1}`，同轮询）——规格逆向自夸克桌面端 `t.copy`（3.24.0 renderer，copy_source=1）。
- **转存四步链**：① `share/sharepage/token`（`{pwd_id,passcode,support_visit_limit_private_share:true}`→`data.stoken`，pwd_id=链接 `/s/` 后段）② `share/sharepage/detail`（GET，`pwd_id/stoken/pdir_fid=0/force=0` 分页，`data.is_owner=1` 则是自己文件无需转存；每项取 `fid`+`share_fid_token`）③ `POST share/sharepage/save`（挂 `drive-pc.quark.cn`，与全量 clouddrive 端点同主机；`{fid_list,fid_token_list,to_pdir_fid,pwd_id,stoken,pdir_fid:"0",scene:"link"}`→`data.task_id`）④ 轮询 task（`data.save_as.to_pdir_name`=落地目录名）。**协议级验证**：QuarkProbe 自造分享→SaveShare 全链被服务器正确应答（自分享返回 `这是你自己网盘里的文件，无需转存`——服务器走到了归属判定，非协议失败）；外部他人分享链接的落盘验收待用户提供链接。
- **创建分享三步链**：① `POST share`（`{fid_list,title,url_type,expired_type[,passcode]}`，`url_type` 1公开/2私密，`expired_type` 永久=1/1天=2/7天=3/30天=4→`data.task_id`）② 轮询 task 取 `data.share_id` ③ `POST share/password`（`{share_id}`→`data.share_url/passcode/pwd_id`；私密链接=`share_url+"?pwd="+passcode`）。
- **分享列表**：`GET share/mypage/detail`（`_page/_size/_sort=created_at:desc`，每项 `share_id/share_url/title/first_fid/status/created_at/expired_at/file_num`）。**列表不含提取码**，要取得逐个调 `share/password`（P2 UI 不展示）。
- **删除分享**：`POST share/delete`（`{share_ids:[…]}`）。
- **上传五段链**（QuarkPan 独有，含 up 端点与 hash_ctx 算法，P2 阶段3实现）：`file/upload/pre`→`file/update/hash`→`file/upload/auth`+PUT `https://{bucket}.pds.quark.cn/{obj_key}?partNumber=&uploadId=`→合并 auth+POST→`file/upload/finish`。分片大小取 `pre` 响应 `metadata.part_size`（服务端下发，客户端校验须为 65536 的倍数；缺省 4MB）；`authorization` 头=auth_key；`X-Oss-Hash-Ctx`=SHA1 增量中间态（不做最终 padding 的 5 个 uint32 组 JSON 后 base64，Nl=已处理位数低 32 位、Nh=高 32 位，与桌面端 getHashCtx 一致），仅 partNumber≥2 带。秒传命中两处体现：`pre` 响应 `finish=true`（直接出结果），`update/hash` 响应 `finish=true`（桌面端抛 FLASH_FINISH、`end(t.data)` 直接用响应 data 作结果）；`repeat_backup=true` 桌面端抛 REPEAT_BACKUP（备份重复）。

**参考**：[quarkpan](https://pypi.org/project/quarkpan/)（Python，接口最干净的移植对象）、[QuarkPanTool](https://github.com/ihmily/QuarkPanTool)（转存/批量分享）、[OpenList quark 驱动](https://doc.oplist.org/)（在线预览参数参考）。

## 4b. 百度分享实测规格（2026-10-14，BaiduProbe 6/6）

- **端点**：`POST https://pan.baidu.com/share/pset`（不是 `share/set`——后者按旧文档签名法报 `errno=-3`）。
- **鉴权**：纯 Cookie（BDUSS+STOKEN），**不需要** bdstoken、不需要 query 参数。
- **表单**（`application/x-www-form-urlencoded`）：`path_list=["/路径1","/路径2"]`（按**路径**不是 fs_id）、`schannel=4`（私密）、`channel_list=[]`、`period=0`（0=永久，1/7/30=天数）、`pwd=<4位提取码>`、`share_type=9`。
- **响应**：`{errno, shareid, link, ...}`；`link` 即 `https://pan.baidu.com/s/1xxxxx`。与 `pwd` 拼 `?pwd=` 给接收方。
- **取消**：`POST share/cancel`，表单 `shareid_list=[12345]`，同样纯 Cookie 无 query。
- **百度已取消无提取码公开链接**：pwd 传空/不传会被拒（BaiduPCS-Go 在客户端随机生成 4 位码后重发）。客户端策略：未指定时随机生成（去掉易混字符 ilo01）。
- 列表/改密/密码查询另有 `share/record`（GET，page/desc/order=time）、`share/surlinfo`（GET，shareid+sign）——本项目未用，备查。
- **转存全链（2026-10-15 改为接口取元数据并端到端实测通过；实现在 src/Pandre.Core/Baidu/BaiduPanClient.cs 的 SaveShareAsync）**：
  1. 归一键：兼容 `https://pan.baidu.com/s/1xxx` 与 `share/init?surl=xxx`；`/s/` 后段缺首字符 `1` 时补上。
  2. **提取码校验**：`POST share/verify?surl=<key 去掉首字符 1>&bdstoken=<t>&t=<ms>&channel=chunlei&web=1&clienttype=0&app_id=<PanAppId>`，表单 `pwd/vcode/vcode_str`。**必须带 `Referer` 指向分享页**：无 Referer 实测 `errno=2`；`surl` 带首字符 `1` 实测 `errno=105`（`verify[surl去1+Referer]` 才 `errno=0` 并返回 `randsk`）。`randsk` 只走 **Cookie `BDCLND`**（必须手动注入 Cookie 容器）。**调校验前先删旧的 `BDCLND`**，否则上一个链接的提取码会串味。`errno=105` = 分享不存在/已失效。
  3. **分享元数据与根层文件：走接口，不解析分享页**：
     - `GET /api/shorturlinfo?shorturl=<完整 key，带首字符 1>&web=1&app_id=<PanAppId>&channel=chunlei&clienttype=0` → `shareid`（int64）+ `uk`（分享者）。**此接口 errno 即使非 0（实测 -3/-9/-21）也可能带着完整数据**，判据是字段在不在，不是 errno。
     - `GET /share/list?shorturl=<key 去掉首字符 1>&root=1&web=5&num=100&page=N&dir=%2F&channel=chunlei&app_id=<PanAppId>&clienttype=0` → `list[].fs_id`（**字符串**形态，兼容数字）。带提取码的分享必须先验过才有 `BDCLND`，否则 `errno=-9`。分页到不足 `num` 为止。
     - **页面解析法已废**（2026-10-15 实测）：netdisk 客户端 UA 拿到的是约 5.8KB 精简页，既无 `locals.mset` 也无文件列表；浏览器 UA 页面的内嵌字段随模板漂移。四种取法（netdisk/浏览器 UA × 带不带 Referer）都取不到 `fs_id`。旧实现依赖 `locals.mset`，导致任何链接都报「分享页解析失败（locals.mset 未找到）」。
     - **注意两个 shorturl 口径相反**：`shorturlinfo` 要**完整 key**（带首字符 1），`share/list` 要**去掉首字符 1**；`share/verify` 的 `surl` 同样去掉首字符 1。
  4. **转存**：`POST share/transfer?shareid=<id>&from=<uk>&bdstoken=<t>&channel=chunlei&web=1&clienttype=0&app_id=<PanAppId>&ondup=newcopy`，表单 `fsidlist=[…]`（**根层 fs_id 逐个列出**）、`path=<目标父目录>`（目录须已存在；传目录的 fs_id 一次即递归整棵子树）。**必须带 `Referer` 指向分享页**：带上才是业务应答（自转自己：`errno=2` + `show_msg:"文件已存在"`），不带只剩 `{"errno":2,"request_id":…}` 的参数级拒绝（客户端默认 Referer 是 `disk/home`）。`ondup` 固定在 query。
  - errno 映射（实现里的用户可读文案）：`-4/-6` 登录态失效；`-8/4` 目标目录已有同名；`-10/20` 容量不足；`2` 参数错误或目标目录不存在（有 `show_msg` 时直接透出，如「文件已存在」）；`12` 转存文件数超限（免费号单次约 500 项）；`111` 请求过快；`-21` 分享已被取消或删除（`show_msg`「来晚啦，该分享已被取消」）；`140` 链接出错。
  - **端到端实测（2026-10-15）**：用公开的他人分享 `https://pan.baidu.com/s/1joRvLQ7nbti0Wp4t2CkX5w`（提取码 `ZMTD`）真实转存，落盘 `【紫马课堂】课程目录.zip`（5,687,504 字节）于自建目录 `/转存验证`，随后删除文件与目录。全链 `verify(errno=0 + randsk) → shorturlinfo(shareid+uk) → share/list(errno=0) → transfer(errno=0)` 通过。另有 5 条已取消的外部分享用作 `errno=-21` 分支实测（`share/list` 的 `show_msg` 正是「来晚啦，该分享已被取消」）。
  - 附带修复：`api/create`（新建文件夹）等端点响应头写 `Content-Type: …; charset=utf8`（无连字符），.NET 的 `Encoding.GetEncoding("utf8")` 不认这个别名，`HttpClient.GetStringAsync` 直接抛 `'utf8' is not a supported encoding name`（**新建文件夹曾因此必失败**）。已在 `src/Pandre.Core/PanHttp.cs` 的 HTTP 管道里用 `CharsetFixHandler` 统一归一 charset，两盘共用，调用点不必各自兜底。

## 4c. 百度秒传链接：三条通道的当期判决（2026-10-14，结论=不可用）

测试对象用**公开样例**（非自有文件），以排除「服务端不认识这个哈希」的干扰：`md5=d5aabefc3290f7a3c09912228b136d0c`、`slice-md5=821a9f0d27fcd19c80474d2140ed2d85`、`size=6467659`、`name=test.exe`（`rapid-upload-userscript-doc` 文档里的标准样例）。

| 通道 | 请求 | 实测结果 |
|---|---|---|
| A. v1 `/api/rapidupload` | `POST pan.baidu.com/api/rapidupload?app_id=250528&bdstoken=…&channel=chunlei&clienttype=0&rtype=1&web=1`，表单 `path/content-md5/slice-md5/content-length` | **全矩阵 `errno=2`**：浏览器 UA / netdisk UA / +Referer / +X-Requested-With / 去掉 bdstoken / md5 大小写，全部一样。UA 变体已排除「2022-10-24 起缺 UA 报 errno=2」这一历史原因 |
| B. v2 minimal precreate | `POST pan.baidu.com/api/precreate`，`block_list=["<content-md5>"]` + `autoinit=1`，`rtype` 2 / 3 各试 | 两者都回 `return_type=1`（= 要求真传），`block_list:[0]`。原因：`block_list` 要的是**按 4MB 分片的逐块 md5 表**，单元素整文件 md5 对不上（>4MB 的文件必然失配） |
| C. 古典 PCS | `POST pcs.baidu.com/rest/2.0/pcs/file?method=rapidupload&app_id=266719` + Cookie | `{"error_code":31045,"error_msg":"user not exists"}`——PCS 端点认 **OAuth access_token** 身份，Cookie 会话无效 |

**根因**：bdpan:// 链接只携带 `content-md5` + `slice-md5`，而当前唯一可用的服务端校验入口是 precreate，它要求逐块 md5 表；逐块 md5 无法由整文件 md5 与首 256KB 切片 md5 反推。v1 端点对 Cookie 会话已停用，古典 PCS 端点只认 access_token。故当期无可用通道，产品侧不做秒传导入。

- 上传链路的秒传命中（`src/Pandre.Core/Baidu/BaiduPanClient.cs` 的 `UploadAsync`，precreate 传真实逐块 md5 表，`return_type=2`）**不受影响**，工作正常。
- 省下的复算：`src/Pandre.Core/Baidu/BaiduPanClient.cs:141` 注释里「秒传 data_offset 依赖」的 uk 取值仍然需要（上传预创建要用），保留。
- **`filemetas` 返回的 md5 对大文件普遍是脏值**（实测拿到过含字母 `o` 的 `0c4693b17od4c9aa34876e7b83536502`）；dlink 带 `Range` 请求的响应也**没有 `Content-MD5` 头**。即「从盘上已有文件反推签名」这条取数路子也不通。

## 5. 技术栈与工程约定

- **.NET 10 LTS + Avalonia UI（Fluent 主题）**，MVVM 用 `CommunityToolkit.Mvvm`。本机 Windows 11，需装 .NET 10 SDK（开工时由 Agent 安装）。原定的 .NET 8 于 2026-11-10 停止支持，2026-10-13 决策时距停服仅剩约一个月，故上移。
- **跨平台决策（已锁）**：原计划 WinUI 3 已改为 Avalonia——用户要求像 [Ghost Downloader 3](https://github.com/XiaoYouChR/Ghost-Downloader-3)（PySide6+Fluent Widgets，四平台）一样支持 Windows + macOS + Linux。选 Avalonia 的理由：保住「纯 C# 直连」核心决策，协议层零改动；Fluent 主题外观接近 WinUI；发布节奏：**Windows 先行 → macOS/Linux 标 beta**。Android 明确不做（用户已否决：维护成本不成比例）。CI 参考 Ghost Downloader 3 的 GitHub Actions 多系统矩阵（仅参考 CI 结构，不参考代码）；macOS 无开发者证书，发布说明里注明用户右键打开（开源项目可申请 SignPath 免费签名）。
- 下载引擎：Windows 内嵌 **aria2c** 官方二进制子进程（成熟的多线程/断点续传），不要自己造轮子。**macOS/Linux 的下载方案推迟到 P3 再定**——aria2 官方只发 Windows 包，届时在「第三方预编译（需校验哈希）/ 用户自装 / 自写 C# 下载器」中按实况三选一。发布包须附带 aria2 的 GPL-2.0 许可证文本（子进程聚合分发，不传染本项目许可证）。
- 打包：各平台单文件自包含，绿色免安装。**不写注册表、不加右键菜单、不进「此电脑」、不开机自启**——这是设计规范，不是可选项。
- **Cookie 落盘必须加密**（BDUSS 等于百度全站通行证）：Windows 用 DPAPI（当前用户）、macOS 用 Keychain、Linux 用 libsecret，无密钥环环境降级为文件权限 600。
- 网络：应用自身的 HTTP 请求（网盘接口）跟随系统代理；**下载引擎 aria2c 不继承系统代理**（见 §7 下载链路的实测结论）。不做应用内代理开关。零遥测：代码里不存在任何统计/上报 SDK。
- 更新机制（P3）：设置页放「检查更新」按钮跳 GitHub Release，不做自动下载替换（避免杀软误报）。
- 实际目录结构（P1 起定型，P2 在此之上扩展）：

```
Pandre.slnx
  src/Pandre.Core/        # 无 UI 依赖：模型、接口抽象 IPanClient、凭据、HTTP
    Baidu/  Quark/
  src/Pandre.Download/    # aria2 封装、队列、断点续传
  src/Pandre.Desktop/     # Avalonia 壳（Windows 先行）：Views/ViewModels
```

- 接口抽象先行：`IPanClient`（List/Search/Rename/Move/Copy/Delete/Download/Upload/Share/SaveShare/OfflineDownload），两家各自实现，UI 只面向抽象。
- **异步纪律（2026-10-14 实修，勿再踩）**：可能被同步等待（`GetAwaiter().GetResult()`）的库方法，内部 await 一律 `ConfigureAwait(false)`——`Aria2Engine.CallAsync` 曾捕获 Avalonia UI 同步上下文，启动时续体要回 UI 线程而 UI 线程正阻塞等它，**死锁**：进程活着、`Responding=True`、aria2c 已起，但主窗口创建了却永不显示（枚举进程窗口 `vis=False`，无 .NET 崩溃日志）。引擎启动放线程池（`Task.Run`）与登录恢复并行。另：`AppServices.InitAsync` 在登录伪弹窗重构后成为无人调用的死代码，导致 `Downloads.Start` 从 P1 起从未执行、app 内下载从未真正可用（P1 E2E 16/16 是控制台探针直接 new DownloadManager 测的，没覆盖 app 启动路径）——**E2E 验收必须走真实 app 路径**，死代码即删。

## 7. 桌面端 UI 结构（Avalonia 12.1.4 实况，勿重复踩）

窗口外观：`ExtendClientAreaToDecorationsHint=True` + `TransparencyLevelHint="Mica, AcrylicBlur"` + `Background=Transparent`，无边框自绘标题栏高度 40 DIP。

- **WindowDecorations 必须用 `BorderOnly`**。Avalonia 12 的 `Window.WindowDecorations` 是枚举 `None / BorderOnly / Full`（默认 Full）。Full 由装饰层自绘标题带：整窗宽、高 40 DIP、**不透明**（装饰模板内部元素不可达，`Button#PART_FullScreenButton` 这类样式能命中按钮，但标题带容器按类型/名字都改不动底色），深色主题下实测呈现纯黑 `rgb(0,0,0)`，覆盖侧栏与内容列，即用户报的「上面黑一条」；且 Full 自带窗口图标与最小化/最大化/关闭/全屏四个按钮，全屏键多余。改 `BorderOnly` 后装饰层只画边框/阴影/缩放手柄，标题带全部由应用内容决定，Mica 直接透出，与主体同材质（实测标题带采样 `rgb(32,32,32)`，与主体一致）。
- **窗口按钮自绘**：标题行右侧 StackPanel，`Button.caption` 46×40、圆角 0、关闭键 hover `#C42B1C`；最大化/还原图标随 `WindowStateProperty` 的 `PropertyChanged` 切换；窗口拖动由 `TitleDragArea` 的 `PointerPressed → BeginMoveDrag`。实测最小化/最大化/还原/关闭、右边缘拖拽缩放（+120px）均通过，圆角与系统阴影保留。
- **托盘图标 + 关闭按钮行为**（2026-10-15 晚新增）：托盘图标常驻通知区域，让应用关窗后仍在后台跑（下载队列不断）。实况要点——
  - 挂载点是 **`Application` 上的附加属性**：`App.axaml` 里写 `<TrayIcon.Icons><TrayIcons><TrayIcon Icon="/Assets/pandre.ico" ToolTipText="盘多录 Pandre" Clicked="OnTrayIconClicked">…`，即 `TrayIcon.SetIcons(Application, TrayIcons)`（反射实测签名 `SetIcons(Application o, TrayIcons trayIcons)`；`Application` 本身**没有** `TrayIcons` 属性，别去找）。`TrayIcon.Icon` 是 `WindowIcon`，`Menu` 是 `NativeMenu`。
  - 关闭行为由设置项 `CloseBehavior`（`exit` / `tray`，默认 `tray`）决定，落地在 `Services/TrayService.cs` + `MainWindow.OnClosing`：`ShouldHideOnClose` 为真时 `e.Cancel = true; Hide();`（隐藏而非关闭，窗口从任务栏消失、进程存活、下载继续）；托盘菜单「退出应用」先置 `TrayService.ExitRequested` 再 `Close()`，走正常退出分支，`Application.Exit` 里照旧收尾 aria2 与两个客户端。托盘左键单击 = 唤回主窗口。
  - 实测（UIA + `CloseMainWindow()`）：发 WM_CLOSE 后进程存活、顶层窗口从 UIA 树消失即隐藏成功；**不要用 `IsWindowVisible` 判断**（本应用窗口恒为 `False`，不可靠）。
  - 设置页对应行在「个性化」卡：`关闭按钮行为` / `点击标题栏关闭按钮时执行的操作`，下拉 `退出应用` / `最小化到托盘`。
- **浏览器接管（2026-10-16 新增）**：网盘网页端选中文件后交给本机 Pandre 下载，替掉官方客户端跳转。四段组成——
  - 应用侧入口 `src/Pandre.Desktop/Services/TakeoverServer.cs`：`HttpListener` 只绑 `127.0.0.1`（外网/局域网物理上够不到），`GET /pandre/ping` 探活，`POST /pandre/add` 走 `X-Pandre-Token` 校验。`TakeoverEnabled` 打开时才随应用启动；关掉时 `AppServices.StopTakeover()` 换一个干净实例（`HttpListener` 停掉后不能复用）。
  - 令牌 `TakeoverToken`：首次访问时 `RandomNumberGenerator.GetBytes(16)` 生成并持久化到 settings.json，安装扩展时写进扩展目录的 `config.js`。**令牌不是可选的**：本机其它进程也能连回环端口，没有它等于给任何本地程序开下载后门。
  - 扩展 `assets/extension/`：MV3，`manifest.json` 按站点分两条 `content_scripts`（`pan.quark.cn/*`、`pan.baidu.com/*`），`background.js` 是 service worker（`importScripts("config.js")` 后 `fetch` 本机入口；service worker 发请求不受私网访问（PNA）策略约束，这条已由 Aria2-Explorer 等先例与官方文档佐证）。内容是 `content-shared.js`（浮动按钮 + 轮询 + 选择读取）+ 站点薄脚本。
  - **选择读取靠 React fiber 反查**：网页行数据不在 DOM 属性上，从勾选框 DOM 取 `__reactFiber$*` 后沿 `return` 上溯（≤24 跳），在每层 `memoizedProps` 里按站点 id 键（百度 `fs_id` / 夸克 `fid`）找文件记录；下钻深度限 2、跳过 `$$typeof` 的元素节点——探到整表数据会拿错文件。取不到时控制台打 `[pandre] 检测到勾选但未能取到文件数据` 供反馈。
  - 安装流：设置页开关 → `ExtensionInstaller.Install()` 把构建产物里的 `extension/` 复制到 `%APPDATA%\Pandre\extension` 并写 `config.js`，然后在资源管理器中打开该目录，由用户到 `chrome://extensions` 加载。**`.crx` 不作为分发形态**：Windows/macOS 的 Chrome 只允许从 Web Store 安装扩展，本地 `.crx` 仅 Linux 允许（Chromium 扩展邮件组结论），离线装还会撞 `CRX_REQUIRED_PROOF_MISSING`；且 .crx 是签名包，改端口/令牌就得重打包重签名，而「已解压目录」允许应用直接覆写 `config.js`——这正是令牌分发能成立的前提。

> **2026-10-15 下载引擎两处网络修复（IPv6 与系统代理）**
> - 现象：下载页出现 `SSL/TLS handshake failure: Error: 操作成功完成。(0)`（aria2 的 WinTLS 后端报文）。
> - 实测一：本机 `d.pcs.baidu.com` 的 DNS 同时返回两条 AAAA 与一条 A，而本机没有 IPv6 出口路由。aria2 一旦选中 AAAA 就立即以 `Network problem has occurred. cause:A socket operation was attempted to an unreachable network` 失败且不回退 IPv4——直连时对同一 dlink 必失败；加 `--disable-ipv6=true` 后同一文件直连下满 35,581,885 字节、退出码 0。
> - 实测二：`aria2c` 作为子进程继承了系统代理（`HTTP_PROXY` / `HTTPS_PROXY` = `http://127.0.0.1:7897`）。aria2 会读取这两个环境变量，于是 `--split=16` 的下载全部挤过本地代理：同一小文件经代理 74 KiB/s、直连 1.6 MiB/s，且 WinTLS 在并发连接上会随机握手失败。
> - 处置：`Aria2Engine.SpawnProcess` 增加 `--disable-ipv6=true`，并在子进程环境里删除 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`。验证方式：应用内 aria2 的 `aria2.getGlobalOption` 回报 `disable-ipv6=true`，且 `all-proxy` / `http-proxy` / `https-proxy` 三项均不存在（修复前会被环境变量填上）。
> - 取证工具：`D:\WorkSpace\WorkBench\pan-re\probe\DlinkProbe\`（`search <关键词>` 在两盘搜文件；`link <baidu|quark> <路径>` 取真实 dlink 与必备请求头）。

> **2026-10-16 下载页删除语义与多选**
> - 删除语义（`DownloadManager.RemoveAsync(t, deleteLocalFiles)`）：未完成任务（排队/下载中/已暂停/出错）总是连过程文件一起删（分片残件 + `.aria2` 控制文件）；已完成任务按 `deleteLocalFiles` 决定是否删成品文件，由界面询问。磁盘清理只允许落在下载目录之内（`Path.GetFullPath` 越界守卫，FileName 来自服务端）。
> - 实测坑：aria2 的 `forceRemove` 返回**之后**才把 `.aria2` 控制文件落盘（供断点续传），只删一遍会被它重建；`WatchDeleteAsync` 短轮询盯删，连续两轮不存在才收手。取证：`D:\WorkSpace\WorkBench\pan-re\probe\DlDeleteProbe\` 三用例全过（下载中删除 → 残件与控制文件俱消；已完成+保留 → 文件在；已完成+删除 → 文件消）。
> - 界面：工具栏「多选」开关 → 行内出勾选框 + 批量条（全选/清空/已选 N 项/删除选中）。已完成任务的删除按钮弹出菜单「仅从列表移除 / 移除并删除本地文件」——菜单项绑定行级命令（`DownloadRowViewModel.RemoveKeepCommand` / `RemoveWithFilesCommand`），因为 Flyout 弹层里 `$parent[ListBox]` 这类祖先绑定取不到外层 DataContext。批量删除的菜单项则直接绑 `DownloadsViewModel`（弹层从工具栏按钮继承 DataContext）。
> - 下载页状态条（`DownloadsViewModel.SetStatus`）：操作反馈 10 秒后自动清空，错误提示 `sticky: true` 保留到下次写入；计时带版本号，期间有新提示则旧计时作废，不会把新提示提前抹掉。
